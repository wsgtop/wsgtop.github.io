# 从零开始学提示工程

随着 GPT、Claude 等大语言模型（LLM）走入日常开发，**能否写出好的提示词（Prompt）** 已经成为新的核心技能。好的提示词能让 AI 交付 90 分甚至满分的答案，差的提示词只会得到一堆看似正确实则无用的废话。

## 一、什么是提示工程？

提示工程不是玄学，而是 **用清晰、精确、结构化的自然语言，向 LLM 描述任务** 的过程。LLM 的本质是"预测下一个最可能的词"，你给它的上下文越充分、约束越明确，它输出的结果就越贴近你的预期。

一个好的提示词通常包含五要素：

| 要素 | 作用 | 示例 |
| ---- | ---- | ---- |
| **角色** | 告诉 AI 它是谁，让它代入专家视角 | "你是一名有 10 年经验的前端架构师" |
| **任务** | 明确告诉它要做什么，不要模糊 | "请重构这段 React 代码" 而不是 "帮我看看这个" |
| **上下文** | 提供执行任务所需的背景信息 | 代码片段、项目背景、用户需求 |
| **约束** | 明确不能做什么、要遵守什么规则 | "不要引入新依赖"、"输出必须是 TypeScript" |
| **输出格式** | 指定回答的结构与形式 | "用表格输出"、"JSON 格式、字段如下" |

## 二、入门三原则

### 原则 1：具体，不要模糊

**❌ 糟糕的提示：**
```
帮我写个网站
```

**✅ 好的提示：**
```
请用 Next.js 14 + Tailwind CSS 写一个博客首页，要求：
1. 顶部导航栏包含 logo、菜单、搜索框、主题切换按钮
2. 首屏 Hero 区展示博客标题、一句 Slogan、CTA 按钮
3. 下方展示最新 6 篇文章卡片，包含封面、标题、摘要、日期
4. 使用响应式设计，移动端适配良好
5. 代码分组件组织，不要都写在一个文件里
```

### 原则 2：给示例（Few-Shot Prompting）

当你需要特定风格或格式时，**给 2-3 个示例** 比描述 100 个字更有效：

```
请将以下产品描述重写成更有说服力的营销文案，风格参考示例：

示例 1：
原文：这双鞋透气。
重写：夏日炎炎，双脚也能自由呼吸 —— 每一步都像踩在云上 ☁️

示例 2：
原文：这款充电宝容量大。
重写：20000mAh 超大能量，陪你从日出看到星河，告别电量焦虑 ⚡

现在请重写：
原文：这个保温杯保温效果很好。
```

### 原则 3：分步思考（Chain of Thought）

对于数学题、逻辑推理、代码分析等复杂问题，加上一句 **"请一步步思考并展示你的推理过程"**，准确率会大幅提升：

```
用户在一个商店买了 3 个苹果和 2 个梨，苹果每个 5 元，梨每个 4 元。
他又买了 1 袋 18 元的薯片，结账时使用了一张满 50 减 10 的优惠券。
请问用户最终实际付了多少钱？

请一步步思考，先列出每个步骤，再给出最终答案。
```

## 三、进阶技巧

### 1. 结构化输出

不要让 AI 自由发挥格式，明确指定输出结构：

```
请分析以下代码的潜在问题，输出 JSON 数组，每个元素包含：
- severity: "error" | "warning" | "info"
- line: 行号
- issue: 问题描述
- suggestion: 修改建议

代码如下：

```js
function foo(arr) {
  for (var i = 0; i < arr.length; i++) {
    setTimeout(() => console.log(arr[i]), 100);
  }
}
```

### 2. 约束幻觉

LLM 会"编"答案，尤其是在它不知道的时候。加上这句约束：

```
如果你不确定答案，请直接说"我不知道"，不要编造内容。
如果有引用，请注明来源出处。
```

### 3. 角色扮演 + 多视角复核

让 AI 同时扮演多个角色，用不同视角审视同一个问题：

```
请扮演三位角色评审我的技术方案：
1. 资深架构师：从可扩展性、性能、可维护性角度挑刺
2. 安全工程师：从安全漏洞、数据隐私、权限角度检查
3. 产品经理：从用户体验、开发成本、上线时间角度评估

方案：我打算用纯前端 localStorage 存用户的登录凭证和订单数据。

请三位分别给出意见，最后给出一个综合建议。
```

### 4. 迭代优化（Self-Correction）

一次输出不满意？让它自己改自己：

```
请阅读你刚才生成的代码，然后：
1. 找出其中可能存在的 Bug 和性能问题
2. 用更简洁、更符合现代 JavaScript 习惯的方式重写
3. 加上必要的注释和 JSDoc 类型说明
```

## 四、模板速查

### 📝 代码重构模板

```
角色：你是一名资深 {编程语言} 工程师，推崇简洁、可测试、高性能的代码风格。

任务：请重构以下代码。

上下文：这段代码在 {项目/模块} 中使用，作用是 {简要说明}。

约束：
- 必须保持原有功能不变，所有外部接口签名兼容
- 不要引入项目中没有的第三方依赖
- 要考虑异常处理和边界情况
- 性能要至少与原版持平或更好

输出要求：
1. 先列出原始代码的主要问题（3-5 条）
2. 给出重构后的完整代码
3. 解释做了哪些改动以及为什么

原代码：
{粘在这里}
```

### 📖 长文总结模板

```
请阅读以下文章，输出一份总结报告，包含：
1. 核心论点（一句话）
2. 3-5 个关键要点，每个要点配一句话解释
3. 2-3 个最有启发性的观点或金句
4. 3 个可以立即落地的行动建议
5. 一个值得继续深入思考的问题

要求用中文，通俗易懂，避免原文字面翻译和堆砌术语。

文章内容：
{粘在这里}
```

## 五、避坑指南

1. **不要一次问太多问题**：一个 prompt 一个任务，拆分成多轮对话效果更好。
2. **不要把重要信息藏在长文本末尾**：关键约束放在开头或最后单独强调。
3. **不要迷信一次成功**：优秀的提示词是迭代出来的，先写一版，看输出再调整。
4. **不要忽略系统提示词（System Prompt）**：System 级别的角色设定比用户消息权重更高。

提示工程的本质是 **"把脑子里的隐性知识显性化"** —— 你越清楚自己想要什么，越能清晰地描述出来，AI 就越能成为你的得力搭档。从今天开始，把每一次和 AI 的对话当成练习，你会发现这个技能的回报超乎想象 ✨
